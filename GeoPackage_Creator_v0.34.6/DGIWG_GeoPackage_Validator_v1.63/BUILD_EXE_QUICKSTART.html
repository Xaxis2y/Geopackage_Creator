Building the Standalone .exe

DGIWG GeoPackage Compliance Validator v1.63 — no Python install needed to run it afterward

Anaconda Prompt · PyInstaller · Windows

What this does: packages the validator and its dgiwg_validator package into one self-contained DGIWG_Validator_v1_63.exe that runs on a Windows machine with no Python, no Anaconda, and no pip installs required. You only need Anaconda once — on your own machine, to build the exe. After that, the exe itself can be copied to any Windows PC and just double-clicked or run from a command line.

Building the exe still needs the Anaconda Prompt and the internet (to install PyInstaller and the optional libraries). Running the finished exe afterward needs neither.

1What's in this folder

Three new files handle the build. You already have everything else (the launcher, the dgiwg_validator package, dgiwg_epsg_cache.json).

  • environment.yml — the conda environment definition (Python 3.11 + shapely, Pillow, pyproj, lxml, PyInstaller)
  • 01_create_environment.bat — creates that environment and self-tests it
  • DGIWG_Validator.spec — tells PyInstaller exactly what to bundle (the launcher, the EPSG cache file, and whichever optional libraries are installed)
  • 02_build_exe.bat — runs PyInstaller against the spec file and produces the exe

2Step 1 — Create the environment

1

Open Anaconda Prompt

Start Menu → Anaconda Prompt (not a plain Command Prompt — it needs conda on the PATH). Never install into base; this script creates a dedicated dgiwg environment instead.

2

Navigate to the project folder and run the script

# in Anaconda Prompt
> cd C:\Users\Son\Documents\DGIWG\DGIWG_GeoPackage_Validator_v1.63
> 01_create_environment.bat

This creates (or updates) the dgiwg conda environment from environment.yml, confirms every package imports correctly, and runs the 84-assertion self-test suite so you know the environment is sound before spending time on a build.

3

Check the log

Everything the script did is written to env_setup_log_<timestamp>.txt in this folder. Look for ALL TESTS PASSED near the end. If something failed, that log has the full detail — send it along if you need help diagnosing it.

3Step 2 — Build the exe

1

Run the build script

# same Anaconda Prompt, same folder
> 02_build_exe.bat

This activates dgiwg, confirms PyInstaller is present (installs it if not), cleans any previous build\/dist\ output, runs PyInstaller against DGIWG_Validator.spec, and then smoke-tests the result with --version. It typically takes 1–3 minutes.

2

Find the exe

When it finishes: dist\DGIWG_Validator_v1_63.exe. That single file is the entire application — it embeds the Python interpreter, the dgiwg_validator package, and the offline EPSG cache. Whichever of shapely / Pillow / pyproj / lxml were installed in the dgiwg environment get bundled in too; any that weren't just make the exe fall back the same way the plain .py script does (checks report PASS* instead of failing).

3

Check the log

build_exe_log_<timestamp>.txt has the full PyInstaller output, plus the exe's file size and the result of the --version smoke test.

4Step 3 — Run the exe

What you wantHow
Interactive file picker dist\DGIWG_Validator_v1_63.exe — double-click it, or run it with no arguments. Opens the same file/folder picker window as the Python version.
Validate one file from a shortcut / File Explorer Drag a .gpkg file onto DGIWG_Validator_v1_63.exe (or a shortcut to it). Windows passes the dropped file's path in as an argument automatically.
Command line, single file DGIWG_Validator_v1_63.exe path\to\file.gpkg
Command line, whole folder DGIWG_Validator_v1_63.exe path\to\folder --recursive
Batch QA, quiet, offline, custom report folder DGIWG_Validator_v1_63.exe --recursive --offline --quiet --output-dir .\reports .\data
See every option DGIWG_Validator_v1_63.exe --help

All flags documented in README.md and QUICKSTART.html work identically on the exe — it is the same program, just packaged differently.

5Sharing the exe with someone else

dist\DGIWG_Validator_v1_63.exe is self-contained. Copy that one file to another Windows PC and it runs with no Python, no Anaconda, and no internet connection needed for the validator itself (only --offline-affected checks need internet, exactly like the .py version). You do not need to copy dgiwg_validator\ or dgiwg_epsg_cache.json alongside it — both are embedded in the exe.

The exe is built for the Windows architecture it was built on (64-bit Windows in the normal case) and is not portable to Linux or macOS — rebuild from source there instead.

6Troubleshooting

SymptomWhat to do
Windows SmartScreen or antivirus flags/quarantines the exe Common and expected for unsigned PyInstaller executables — it isn't a sign of a real problem. Click "More info → Run anyway", or add this project folder to your antivirus exclusions before building. The tool is not code-signed.
A console window flashes open and closes immediately Run it from a Command Prompt instead of double-clicking, so the error message stays on screen: dist\DGIWG_Validator_v1_63.exe --version
02_build_exe.bat fails with "Access is denied" on dist\ Close any running copy of DGIWG_Validator_v1_63.exe first, then re-run the script.
Rebuilding after you changed the validator's code Just run 02_build_exe.bat again — it cleans build\/dist\ and rebuilds from whatever is currently in dgiwg_validator\.
exe reports "PASS*" everywhere it didn't used to The environment used to build it was missing shapely / Pillow / pyproj / lxml. Re-run 01_create_environment.bat to confirm those import cleanly, then re-run 02_build_exe.bat to rebuild with them included.
exe file looks large (tens of MB) Expected — it embeds a full Python interpreter plus shapely/Pillow/pyproj/lxml and their native libraries. That is normal for a PyInstaller one-file build.
