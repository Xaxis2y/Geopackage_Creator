🛡 DGIWG GeoPackage Compliance Validator

Quick Start — read this first. Five minutes end to end.

Version 1.62  •  DGIWG STD-DP-19-005 v1.1 (GeoPackage Profile 1.4, Ed. 1.1)

1What this tool does

You hand it a GeoPackage (.gpkg). It checks that file against the 37 numbered requirements of the DGIWG GeoPackage profile, grades each one, and writes you a report that says what passed, what failed, why it failed, and how to confirm the finding yourself in DB Browser for SQLite.

Use it to decide whether a deliverable is fit to accept — before it is accepted, not after.

🔍 It inspects

CRS definitions and WKT, extensions, tile pyramids, zoom levels, metadata documents, geometry validity, bounding boxes.

📝 It produces

An HTML report per file, a matching JSON file, and a roll-up HTML + CSV across a whole batch.

🔒 It never writes

The GeoPackage is opened strictly read-only. Your source file cannot be modified by this tool.

What it can and cannot decide for you

  • Checks 34 of the 37 requirements automatically.
  • Req 1 and Req 2 (OGC base conformance) need the OGC CITE TeamEngine suites — reported as SKIPPED.
  • Req 6 (conditional extensions) depends on your product profile — reported as SKIPPED.
So a clean verdict is not a certificate. It means the 34 automatable requirements are satisfied. Full conformance still requires the three checks above to be carried out separately. Every report states this at the top.

2Set up once (Anaconda Prompt)

Never install into the base environment. Create a dedicated one. Installing into base is the most common cause of dependency conflicts and unexplained runtime failures on these machines. 
# Open Anaconda Prompt, then:
(base) > conda create -n dgiwg python=3.11 -y
(base) > conda activate dgiwg
(dgiwg) > pip install shapely Pillow pyproj lxml

Python 3.11+ is required. Install the locked-compatible validation dependencies with pip install -r requirements.txt. The four packages below unlock the deepest checks:

The four packages above unlock the deepest checks:

PackageWithout it
shapelyReq 24 geometry validity degrades to a partial pass
PillowReq 26 tile pixel-size decoding degrades to a partial pass
pyprojReq 13 datum-name cross-check degrades to a partial pass
lxmlReq 18 metadata XSD structure check is skipped — the report says so explicitly

Nothing breaks if they are missing. The affected requirement simply reports PASS* and tells you which library would have deepened the check.

3Run it

  1. Point it at a file or a folder

    (dgiwg) > cd C:\Users\Son\Documents\DGIWG\DGIWG_GeoPackage_Validator_v1.62

# one file
(dgiwg) > python DGIWG_Validator_v1_62.py "C:\Data\my_file.gpkg"

# every .gpkg in a folder
(dgiwg) > python DGIWG_Validator_v1_62.py "C:\Data\Project_Alpha"

# no arguments at all -> a file-picker window opens
(dgiwg) > python DGIWG_Validator_v1_62.py

    python -m dgiwg_validator does exactly the same thing and works from any folder once the package is on your path.

  2. Wait for the summary

    Progress is printed as it goes, then a per-file verdict:

      Verdict : LIKELY CONFORMANT (partial checks)
  PASS    : 24
  FAIL    : 0
  PASS*   : 6
  SKIPPED : 7

  3. Open the HTML report

    Reports land in a reports\ subfolder next to your GeoPackage (or wherever --output-dir points).

    FileWhat it is
    <name>_DGIWG_Report.html Start here. Every requirement, its status, the evidence, the likely cause, and a ready-to-run SQL query to confirm it yourself.
    <name>_DGIWG_Report.json The same results, machine-readable, for scripting or archiving.
    DGIWG_GPKG_FINAL_REPORT.html Batch roll-up: every file side by side, a file × requirement matrix, confidence ratings.
    DGIWG_GPKG_FINAL_REPORT.csv The roll-up as a spreadsheet.

4Reading the result

StatusWhat it meansWhat you do
PASS Fully checked and met. Nothing.
PASS* Partial pass. The structure is right, but something could not be verified automatically — an optional library is missing, the run was offline, or the requirement is not fully automatable. Open the Manual Confirmation panel in the report and run the SQL it gives you.
FAIL Checked and not met. The detail names the offending table, value or CRS. Send it back to the producer. The tool is read-only — it cannot fix the file.
ERROR The validator could not complete this check. It is deliberately different from a data failure. Keep the report and send it for validator review; do not mark the dataset non-conformant from this status alone.
SKIPPED Not applicable to this file (e.g. a vector-CRS check on a tiles-only file), or needs external context (Req 1, 2, 6). For Req 1, 2 and 6 — verify separately.

The file verdict

VerdictCondition
CONFORMANT Every requirement was executed and passed.
AUTOMATED CHECKS CONFORMANT — EXTERNAL REVIEW REQUIRED Automated checks passed, but one or more requirements were skipped and need external evidence.
LIKELY CONFORMANT (partial checks) No FAIL, but one or more PASS* still need a human to confirm.
NON-CONFORMANT One or more FAIL.
VALIDATION ERROR — REVIEW REQUIRED The validator itself could not complete one or more checks.
Running with --offline caps some CRS checks at PASS*, because the EPSG registry cannot be reached to confirm them. On an air-gapped network, LIKELY CONFORMANT is the normal best outcome — not a problem with your file.

5Options worth knowing

FlagUse it when
--offlineAir-gapped or restricted network. Disables every internet check instead of waiting for timeouts.
--no-installLocked-down machine. Suppresses the optional-library install prompts.
--recursiveThe GeoPackages sit in nested subfolders.
--output-dir FOLDERYou want every report collected in one place.
--quietBatch QA. One summary line per file, nothing else — ideal piped to a log.
--fail-fastStop at the first non-conformant file or validator error. Exits with code 1, so it works in a script.
--sample-size NDeeper geometry/tile sampling for Req 24 and Req 26 (default 25). Slower, broader.
--timeout SECONDSSlow link (raise it) or unresponsive endpoints (lower it). Default 8s.
--versionConfirm which build you are running.

The two commands people actually use

# Air-gapped single-file check
(dgiwg) > python DGIWG_Validator_v1_62.py --offline "C:\Data\my_file.gpkg"

# Batch QA: one line per file, all reports in one folder
(dgiwg) > python DGIWG_Validator_v1_62.py --offline --quiet ^
             --output-dir "C:\QA\reports" "C:\Data\Project_Alpha"

6If something goes wrong

SymptomCause and fix
ModuleNotFoundError: dgiwg_validator The launcher was moved away from the dgiwg_validator\ folder. Keep the two together.
File skipped — not a valid GeoPackage The file is not SQLite, is truncated or encrypted, or has no gpkg_contents / gpkg_spatial_ref_sys. Batch runs continue past it.
The checks hang for a long time Internet checks are timing out. Re-run with --offline, or lower --timeout.
No file-picker window appears tkinter is not present in that environment. Pass the file or folder path on the command line instead.
More PASS* than expected An optional library is missing, or the run was offline. The report names the reason on each affected row.
Reports are not where you expect The target folder was read-only, so reports went to a temp folder — the console prints the path it used.

Verify your install

The bundled self-test builds synthetic GeoPackages, validates them, and checks every result against an expectation table. It writes local_test_log_<timestamp>.txt next to itself.

(dgiwg) > python run_local_tests.py

Expected on the last line: ALL TESTS PASSED. If not, send the log file for analysis.

7Going deeper

This page is the five-minute version. The full User Manual (v1.62, .docx) ships in the same folder and covers the complete requirement-by-requirement coverage table, confidence ratings, the forensic source-software detection, and the manual-confirmation workflow in detail.

Every FAIL and PASS* row in the HTML report already carries its own Manual Confirmation panel: what to check, how to check it in DB Browser for SQLite, and a SQL query you can paste straight in.
