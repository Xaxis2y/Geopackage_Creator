# IMPORTANT: GDAL Installation Required!
# =======================================
# GDAL must be installed separately due to system dependencies.
#
# PIN THE VERSION. (v0.30.7, moved to 3.13.2 in v0.30.13)
# --------------------------------------------------------
# Required: GDAL == 3.13.2   (the build this release was tested against)
#
# Pin it because reproducible releases need a known build, not because any
# other version is believed broken. An unpinned
# `conda install -c conda-forge gdal` silently moved this project from 3.13.1
# to 3.13.2 between the v0.30.6 build and its release test, which made a
# genuine bug in our own code look like a GDAL regression. Always pass the
# version.
#
# v0.30.13: the pin itself moved from 3.13.1 to 3.13.2. This is NOT because
# 3.13.1 was found to be broken - it wasn't - and it is NOT a fix for
# anything. A separate 2026-08-04/05 access violation was bisected to an ABI
# mismatch between the installed lxml build and the libxml2 conda resolves at
# runtime (see core/metadata_handler.py, "LIBXML2 ABI FAIL-FAST GUARD", and
# CHANGELOG_v0.30.13.md); that crash reproduced under GDAL 3.13.1 and is
# independent of which GDAL patch version is installed. lxml>=4.9.0 above is
# therefore not enough on its own - what matters is that lxml and libxml2
# come from a SINGLE consistent conda solve. Prefer:
#   conda env create -f environment.yml
# over installing lxml via pip into a conda environment that already has GDAL.
#
# Option 1: Conda (Recommended)
#   conda install -c conda-forge gdal=3.13.2
#
# Option 2: OSGeo4W (Windows)
#   Download from: https://trac.osgeo.org/osgeo4w/
#   Install GDAL during setup
#
# Option 3: System Package Manager
#   Ubuntu/Debian: sudo apt-get install gdal-bin python3-gdal
#   macOS: brew install gdal
